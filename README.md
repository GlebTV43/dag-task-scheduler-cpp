# Task Scheduler — граф зависимых вычислений

Библиотека `TTaskScheduler` для построения графа зависимых задач и получения их результатов по требованию. В качестве приложения реализованы рекомендации мест с учётом геолокации и погоды.

Лабораторная работа №9 по C++ в ИТМО.

## Возможности

- Добавление вызываемых объектов и их аргументов через `Add`.
- Ленивое получение результата и выполнение всех задач через `ExecuteAll`.
- Связывание задач через `TFuture` и продолжения `Apply`.
- Проверка циклических зависимостей и повторного перемещения результата.
- Приложение с запросами к 2ip, Open-Meteo и Geoapify.

## Что изучено и применено

- Графы зависимостей, DAG и отложенные вычисления.
- Variadic templates, специализации и собственные type traits.
- Perfect forwarding, ссылки и семантика перемещения.
- Собственные Tuple, Invoke и последовательности индексов.
- Стирание конкретного типа задачи через базовый класс и владение через unique_ptr.
- Разделение контроллера, сервиса, репозиториев и HTTP-клиентов; GoogleTest.

## Сборка

Требуются компилятор с поддержкой C++23 и CMake 3.20 или новее. Команды выполняются из корня репозитория. При первой настройке CMake загружает тестовые или сетевые зависимости, поэтому нужен интернет.

```sh
cmake -S . -B build
cmake --build build --parallel
```

В Visual Studio и других генераторах с несколькими конфигурациями добавьте `--config Debug` к команде сборки. Исполняемые файлы в таком случае могут находиться в подкаталоге `Debug`.

## Тесты

В проекте есть тесты GoogleTest.

```sh
cmake --build build --target processing-lib-tests
ctest --test-dir build --output-on-failure
```

Для генераторов с несколькими конфигурациями используйте `--config Debug` при сборке и `-C Debug` при запуске CTest.

## Использование

Для демонстрационного приложения нужны собственные ключи 2ip и Geoapify. Создайте `src/data/2ip_apikey.txt` и `src/data/geoapify_apikey.txt`, записав в каждый соответствующий ключ одной строкой. Эти файлы исключены из Git.

Соберите проект, затем запускайте приложение из каталога `build`, чтобы пути к файлам ключей соответствовали исходному коду:

```sh
cd build
./bin/labwork9
```

Для использования самого планировщика сетевые ключи не нужны.

В исходной версии приложение содержит относительный include `../lib/TTaskScheduler.hpp` в `src/servicies/RecommendationService.hpp`. При сборке приложения его может потребоваться заменить на `../../lib/TTaskScheduler.hpp`; библиотека и тесты от этого include не зависят.
